# تشغيل منصة أسماك البركة للزبائن

هذه أول حزمة للواجهة العامة ومخطط قاعدة البيانات. لا تعتبر المنصة منشورة أو متصلة قبل إكمال الإعداد والاختبار.

## الملفات
- `web/index.html`: واجهة عربية متجاوبة للزبائن، تعرض الأصناف وتجمع سلة الحجز والبيانات.
- `supabase/schema.sql`: الجداول وسياسات القراءة العامة ودالة إنشاء الطلب بشكل ذري، مع إعادة حساب السعر على الخادم.

## إعداد قاعدة البيانات
1. أنشئ مشروع Supabase باسم Asmak Albaraka من حسابك.
2. افتح SQL Editor وشغّل كامل ملف `supabase/schema.sql`.
3. أضف أصناف الأسماك الحقيقية وأسعارها في `cloud_fish_products`. لا توجد أصناف أو أسعار افتراضية في المشروع.
4. خذ Project URL وPublishable/anon key من إعدادات المشروع.
5. ضع القيمتين في أعلى `web/index.html` بدل `YOUR_SUPABASE_URL` و`YOUR_SUPABASE_ANON_KEY`.
6. انشر مجلد `web` على استضافة HTTPS مثل GitHub Pages أو Cloudflare Pages.

## الأمان
- استخدم مفتاح Publishable/anon فقط في المتصفح.
- لا تضع service_role key أو كلمات مرور قاعدة البيانات في HTML أو GitHub.
- سياسة RLS تسمح بقراءة الأصناف النشطة فقط. لا توجد سياسة قراءة عامة للطلبات.
- إنشاء الطلب يتم عبر RPC تتحقق من المدخلات وتقرأ السعر من قاعدة البيانات بدل الثقة بسعر المتصفح.
- لا تفتح الإدارة أو بيانات الزبائن للعامة. ربط لوحة الإدارة بحساب موثّق وصلاحيات مدير هو مرحلة لازمة قبل التشغيل التجاري.

## ما لم يكتمل بعد
- مزامنة تطبيق Flutter الإداري مع قاعدة البيانات السحابية (رفع الأصناف ومشاهدة/تحديث الطلبات).
- دخول المدير وصلاحياته.
- رسائل تأكيد/واتساب أو SMS، متابعة حالة الطلب للزبون، وسياسة الخصوصية.
- إعداد الدومين والنشر الفعلي، واختبار رحلة حجز كاملة.
- مراجعة قانونية/تشغيلية محلية قبل إعلان الخدمة كمنصة تجارية رسمية.

## الاختبار
اختبر أولًا بمشروع Supabase تجريبي وبيانات وهمية. تأكد من عدم إمكان قراءة الطلبات دون صلاحية، ومن أن السعر النهائي يؤخذ من قاعدة البيانات. لا تستخدم بيانات زبائن حقيقية قبل استكمال ضوابط الخصوصية.
