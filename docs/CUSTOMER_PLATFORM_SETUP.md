# تشغيل منصة أسماك البركة للزبائن

هذه حزمة تأسيس للمتجر وقاعدة البيانات. لا تعتبر المنصة منشورة أو متصلة بتطبيق الإدارة قبل إكمال إعداد المدير والمزامنة والاختبارات.

## الملفات
- `web/index.html`: واجهة عربية متجاوبة للزبائن، تعرض الأصناف وتجمع سلة الحجز والبيانات.
- `supabase/schema.sql`: جداول المنتجات والطلبات وتفاصيلها، سياسات RLS، وصلاحيات المدير، ودالة إنشاء الطلب التي تعيد حساب الأسعار على الخادم.

## إعداد قاعدة البيانات
1. افتح مشروع Supabase الحالي: `https://qrvphvimsjhnuqcvnfaw.supabase.co`.
2. افتح SQL Editor وشغّل كامل ملف `supabase/schema.sql`.
3. من Authentication أنشئ حسابًا مخصصًا لمدير المتجر، ثم تحقق من البريد الإلكتروني.
4. بعد إنشاء الحساب، أضف معرف المستخدم UUID إلى جدول `store_admins` من SQL Editor باستخدام:
   `insert into public.store_admins(user_id) values ('ضع-هنا-UUID-حساب-المدير');`
5. أضف أصناف السمك الحقيقية وأسعارها في `cloud_fish_products`. لا توجد أصناف أو أسعار افتراضية.
6. استخدم Project URL وPublishable key فقط في الواجهات العامة. لا تنشر Secret/service_role key مطلقًا.
7. انشر مجلد `web` على استضافة HTTPS بعد الاختبار.

## الأمان
- المتصفح يستخدم Publishable key فقط.
- الزبائن يستطيعون قراءة الأصناف النشطة وإرسال طلب عبر الدالة `place_customer_order` فقط.
- لا توجد صلاحية عامة لقراءة بيانات الزبائن أو الطلبات.
- المدير المضاف إلى `store_admins` فقط يستطيع إدارة الأصناف وقراءة الطلبات وتحديث حالتها.
- الدالة تعيد حساب السعر من قاعدة البيانات ولا تثق بسعر مرسل من المتصفح.
- لا تشارك بيانات دخول المدير أو مفاتيح Secret.

## ما لم يكتمل بعد
- شاشة تسجيل دخول المدير داخل تطبيق Flutter.
- ربط إدارة الأصناف والحجوزات في Flutter بالجداول السحابية ومزامنتها مع قاعدة SQLite الحالية.
- واجهة متابعة حالة الطلب للزبون ورسائل تأكيد واتساب/SMS.
- نشر الموقع واختبار حجز كامل على هاتف فعلي.
- سياسة خصوصية وإجراءات تشغيل مناسبة قبل استقبال بيانات زبائن حقيقية.

## اختبار آمن
ابدأ بأصناف تجريبية وحساب مدير تجريبي. تحقق أن الزائر غير المسجل لا يستطيع قراءة الطلبات أو تعديل الأصناف، وأن المدير المعتمد يستطيع ذلك. لا تستخدم بيانات زبائن حقيقية حتى اكتمال الربط والاختبار.
